# Film mode (Hermes' own workflow, after Lemo-Opuscar)

Source concept: lemomo-ai/lemo-opuscar (MIT; style content CC BY 4.0
per the repo's badge). Only the style-prompt INDEX is bundled here
(`styles-index.md`, generated by the repo from its style.json files);
full style prompts (styles/<name>/STYLE.md) are fetched on demand
when a style is picked, and demo films are never bundled. The desktop
`claude plugin marketplace add/install` commands are NOT used on
Android. Hermes' own MY-STYLES file lives in the user's files
($HERMES_HOME/my-styles.md), not in the repo.

## Style library — 66 styles, not 59

The repo lists 66 ready styles (the social post that circulated said
59 — the repo's own count, verified 2026-10-30 from its styles/
directory: 67 entries minus the `_template` folder, is 66). Browse
`styles-index.md` by family: Edit & Documentary, Evidence Films,
Hand-drawn & Painting, East Asian Traditions, Print & Printmaking,
and more. Each entry gives the style name, folder, and demo film.

## Pipeline (all in code, no video model)

1. STORY + STYLE: the user picks a style from the index OR describes
   their own. A custom style can be saved to MY-STYLES for later films.
2. STORYBOARD first (optional stop): key shots in the real style,
   shown for approval before the full film is built.
3. SCENES IN CODE: story + style become scene-by-scene HTML/GSAP
   scenes, using the existing design pipeline — Huashu flow
   (6 preview candidates → user picks 3 → polish), GSAP skills for
   animation, React Bits components for web prototypes where they fit,
   UI UX Pro Max palettes/fonts as choices.
4. RENDER: in the Alpine sandbox, attempt Chromium + ffmpeg
   (install via apk if missing): render each scene to frames/video,
   then mux music + narration. Music comes from the sandbox music
   tooling the repo documents (requirements-music) or the user's own
   audio file; narration from on-device TTS (requirements-voice) or
   the user's own recording. NEVER generate music with a fake tool.
5. FALLBACK (honest): if a render step genuinely cannot run in the
   sandbox, still deliver the complete coded film — HTML scenes +
   storyboard + narration script + music plan — via the existing ZIP
   export, stating exactly which render step needs a desktop run.

## Output

A complete video file when rendering works (music + narration muxed),
otherwise the coded film package. Both go through the existing
DownloadsExporter/ZIP path. The Film panel reports which step ran
on-phone and which step needs desktop — never blurred.
