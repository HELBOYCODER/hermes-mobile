# Hermes Mobile: World-Class Engineer in Every Pocket

## Product promise
A multilingual mobile AI engineering studio: coding, design, CAD/3D workflows, research, and professional Persian documents. Features must reflect real execution capability, not decorative UI.

## Current verified base
- Native Android Kotlin + Jetpack Compose + Gradle, with CMake/NDK native components.
- Embedded Alpine/PRoot featuring Python, Node.js, Git; bundled Python MCP scripts and skill instructions.
- Spec Kit and Superpowers bundled; remote Context7, GitHub MCP, Serena and Playwright listed with explicit prerequisite states.
- Baseline version 2.5.0; no physical Android device verification claimed.

## Architecture
1. **Android shell (Kotlin/Compose):** responsive workspace, accessible motion, project explorer, editor, artifact previews, chat, terminal, permissions, and download manager.
2. **Agent orchestration service:** planning -> contextual repository discovery -> tool selection -> explicit approval -> patch -> test -> review -> artifact. Stateful task ledger and checkpoints. No claim of Claude Harness source inclusion.
3. **Capability registry:** each skill/tool declares license, provenance/version, platform (native/PRoot/remote), installed/configured/verified state, permissions, health checks, size and dependencies.
4. **Execution runtimes:** local Python/Node/Git for supported operations; optional isolated remote workers for browser automation, Blender, CAD and heavyweight rendering. Not all of these are practical inside an APK.
5. **Model router:** provider-neutral adapters; account entitlements, rate limits and pricing respected. Never bypass provider access controls.
6. **Security:** workspace-scoped filesystem, deny-by-default shell/network operations, user approvals for destructive/high-risk tasks, secrets vault, audit trail, dependency pinning, provenance scanning.
7. **Outputs:** versioned projects plus validated PDF, DOCX, SVG, HTML, CAD DXF and Blender scripts or remote-rendered assets; RTL typography and Persian motifs with licensed embedded assets.

## Milestones and acceptance tests
### M1: truthful inventory and architecture
- Automate inventory from real build files, skills, native libraries, installed binaries and live health probes.
- UI distinctly labels bundled, optional-download, requires-host, configured, and verified.
- Unit tests disallow presenting unavailable tools as runnable.

### M2: dependable coding assistant
- Integrate planning, search, edit diff, Git checkpoint, review and tests into a coherent multi-step agent.
- Apply bounded iteration, timeout, cancellation, token/cost budgets and provenance on each run.
- Test with a sample Kotlin bug and a Python bug: failing test -> patch -> passing test evidence.

### M3: professional design system
- Compose Material 3 design tokens, typography including Persian RTL, adaptive layouts, reduced-motion option, tasteful micro-interactions and reusable editors.
- Web design skill packs for Tailwind, accessible React components, animation and browser validation where available.
- Snapshot tests in light/dark and RTL and real-device checks before release.

### M4: documents and engineering artifacts
- Persian academic PDF templates with RTL shaping, bibliography, and decorative Iranian border templates.
- DXF via supported Python libraries and SVG drawings locally; Blender project generation via scripts plus optional remote Blender render worker.
- Validate generated files by reopening/parsing and visual comparison.

### M5: releases
- ARM64 CI builds, signed release with secure signing keys, SBOM, SHA-256, regression tests and physical-device smoke tests.
- Optional feature packs separately versioned and downloaded; install-size cap is a budget, not a reason to bundle nonfunctional tools.

## Candidate integrations (evaluate before inclusion)
- Anthropic Claude Code's documented concepts and permissioned agent workflow; no unverified copying of private harness internals.
- OpenDesign or other design reference projects **only after exact repository and license validation**.
- github/spec-kit; obra/superpowers; github/github-mcp-server; upstash/context7; oraios/serena; microsoft/playwright-mcp.
- Python document tooling (ReportLab, WeasyPrint, python-docx), ezdxf, Blender Python API on compatible remote worker; licenses, font rights and sandbox support first.

## Explicit non-goals
- Pretending all tools or models run offline.
- Unauthorized reproduction of proprietary products or UI.
- Shipping large binaries without ABI, legal, integrity, performance and compatibility checks.

## Definition of done
A feature is done only with implementation, live invocation evidence, automated tests, capability state, docs, and device verification where applicable.
